# M1 会话协议草案（阶段A）
## ①事件类型与字段
每条消息统一包含字段：
- `session_id`：会话唯一标识，一次完整对话固定不变
- `seq`：消息序列号，整数，单调递增，用于去重、断线补发
- `ts`：时间戳，Unix时间，消息产生时刻
- `type`：事件类型，如 `idle`、`listening`、`thinking`、`tool_calling`、`speaking`
- `payload`：事件负载，不同type携带不同业务数据；工具调用时存放工具名、参数；回复时存放文本内容。

## ②状态机流转
完整状态流转：`idle → listening → thinking → tool_calling → speaking → idle`
1. `idle`：空闲状态，等待用户输入。
2. `listening`：正在接收用户输入。
3. `thinking`：模型正在推理。
4. `tool_calling`：正在发起工具调用，等待工具返回结果；**支持打断，收到打断事件直接跳转回 idle，丢弃未完成推理与工具请求**。
5. `speaking`：输出模型回复内容。

流转结束回到 `idle`，等待下一轮用户输入。

## ③权威与幂等
1. **服务端唯一权威**：全部会话状态以服务端为准；客户端只做展示，不能修改会话状态。
2. **seq序列号实现幂等**：使用`seq`序号做请求去重；重复收到相同seq的事件直接丢弃，避免重复执行工具、重复推送消息。

## ④断线语义
客户端发生断线重连，需要携带客户端本地最后收到的`seq`编号；服务端收到重连请求，补发该seq之后所有未送达事件，恢复会话状态；不重置session_id。
